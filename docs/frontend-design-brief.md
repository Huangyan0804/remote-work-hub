## 1. 产品背景

**Remote Work Hub** 是一款为异步沟通与分布式团队打造的轻量级远程协作工作台，解决三个核心痛点：

1. **跨时区协作**——不知道同事现在是不是工作时间。
2. **任务状态透明化**——任务卡片在谁手上、卡在哪一列。
3. **异步进度汇报**——用日报替代强制同步会议。

**目标用户**：3-20 人的分布式产品/研发团队（含日本、东南亚、北美多地成员）。
**使用场景**：桌面端为主（工作时间长驻一个标签页），移动端仅作查看与轻量操作。

## 2. 设计目标与参考

### 2.1 设计原则

| 原则             | 落地要求                                                                 |
| ---------------- | ------------------------------------------------------------------------ |
| 信息密度优先     | 参考 Jira：一屏内看到尽可能多的成员 / 任务，不滥用大留白与大圆角         |
| 状态一目了然     | 成员在线状态、任务列归属、优先级全部用**颜色 + 文字**双重编码，不靠纯色块 |
| 异步优先         | 时间相关的地方都显示「对方本地时间 / 相对时间」，而非仅 UTC              |
| 失败可见且可恢复 | 每个异步操作都必须有加载、成功、失败三态，失败必须给出「重试」出口       |
| 克制的视觉       | 无渐变、无花哨阴影、无插图；靠层级、留白与 1px 边框建立秩序              |

### 2.2 参考产品

- **Jira**（主要参考）：左侧项目导航 + 顶部全局栏、白底卡片 + 浅灰画布、蓝色主色、彩色 pill 徽章、看板列头计数。
- **Linear**：紧凑列表、细腻的悬浮反馈、键盘可达性。
- **Notion**：表单类页面的分区与说明文字排版。

## 4. 设计系统（Design Token）

### 4.1 色彩

> 采用 Atlassian（Jira）风格中性色阶 + 品牌蓝。亮色为默认；暗色需要保持对比度 ≥ 4.5:1。

**亮色（`:root`）**

| Token                | 值        | 用途                             |
| -------------------- | --------- | -------------------------------- |
| `--background`       | `#F7F8F9` | 页面画布（浅灰，不是纯白）       |
| `--card`             | `#FFFFFF` | 卡片 / 侧边栏 / 顶栏             |
| `--foreground`       | `#172B4D` | 主文字（深蓝灰，非纯黑）         |
| `--muted-foreground` | `#626F86` | 次要文字、说明、时间             |
| `--border`           | `#DFE1E6` | 所有 1px 分隔与卡片边框          |
| `--input`            | `#DFE1E6` | 输入框边框                       |
| `--primary`          | `#0C66E4` | 品牌蓝：主按钮、链接、选中态     |
| `--primary-foreground` | `#FFFFFF` | 主色上的文字                   |
| `--secondary`        | `#F1F2F4` | 次级按钮 / 标签底                |
| `--accent`           | `#E9F2FF` | 悬停 / 选中行底色（浅蓝）        |
| `--ring`             | `#0C66E4` | 焦点光晕（3px，20% 透明）        |
| `--destructive`      | `#C9372C` | 错误、删除                       |

**暗色（`.dark`）**

| Token                | 值        |
| -------------------- | --------- |
| `--background`       | `#1D2125` |
| `--card`             | `#22272B` |
| `--foreground`       | `#B6C2CF` |
| `--muted-foreground` | `#8C9BAB` |
| `--border`           | `#3A3F44` |
| `--primary`          | `#579DFF` |
| `--secondary`        | `#2C333A` |
| `--accent`           | `#26374C` |

**语义色（亮 / 暗两套都要给）**

| 语义       | 亮色底/字            | 暗色底/字            | 用在哪             |
| ---------- | -------------------- | -------------------- | ------------------ |
| 成功 / 在线 | `#DCFFF1` / `#216E4E` | `#1C3329` / `#7EE2B8` | ONLINE、提交成功   |
| 警示 / 忙碌 | `#FFF7D6` / `#946F00` | `#332E1B` / `#F5CD47` | BUSY、截止临近     |
| 危险 / 高优 | `#FFECEB` / `#AE2E24` | `#42221F` / `#FD9891` | HIGH、删除、错误   |
| 信息 / 进行中 | `#E9F2FF` / `#0C66E4` | `#1C2B41` / `#579DFF` | IN_PROGRESS、提示  |
| 中性 / 离线 | `#F1F2F4` / `#626F86` | `#2C333A` / `#8C9BAB` | OFFLINE、TODO      |

### 4.2 字体与排版

| 层级             | 字号 / 行高 / 字重 | 用途                     |
| ---------------- | ------------------ | ------------------------ |
| Page Title       | 20 / 28 / 600      | 页面主标题（团队、看板） |
| Section Title    | 16 / 24 / 600      | 卡片标题、看板列名       |
| Body             | 14 / 20 / 400      | 正文、表单标签           |
| Body Strong      | 14 / 20 / 500      | 任务卡标题、成员姓名     |
| Caption          | 12 / 16 / 400      | 时间、辅助说明、徽章     |
| Mono             | 12 / 16            | 时区 ID（`Asia/Tokyo`）、错误码、日期数字 |

### 4.3 间距 / 圆角 / 边框 / 阴影

- 间距基准 **4px**：常用 `4 / 8 / 12 / 16 / 20 / 24 / 32`。卡片内边距 16px，页面左右留白 24px，卡片之间 16px。
- 圆角：`sm 6px`（徽章内元素）/ `md 8px`（按钮、输入框）/ `lg 10px`（卡片）/ `xl 14px`（弹窗）。**不要用超过 14px 的圆角**。
- 边框：一律 1px `--border`；不使用时不要用阴影代替。
- 阴影：仅弹窗与下拉使用 `0 8px 24px rgba(9,30,66,.15)`；普通卡片默认**无阴影**，hover 时可选极轻的 `0 1px 3px rgba(9,30,66,.12)`。

### 4.4 关键尺寸

| 区域             | 尺寸                                             |
| ---------------- | ------------------------------------------------ |
| 顶部全局栏       | 高 56px，白底，底部 1px 边框                     |
| 左侧导航         | 宽 240px（可折叠至 56px），白底，右侧 1px 边框   |
| 内容区最大宽度   | 1280px（团队 / 日报 / 设置页），看板页不限制宽度 |
| 看板列           | 宽 300px，列间距 16px，列头高 40px               |
| 看板卡片         | 最小高 88px，内边距 12px，卡片间距 8px           |
| 移动端断点       | `< 768px` 侧边栏收进汉堡菜单；`< 1024px` 看板横向滚动 |

## 6. 逐页设计需求

### 6.1 登录 / 注册（`/login`、`/register`）

**目标**：让用户在 10 秒内完成登录，并清晰感知失败原因。

```
┌───────────────────────────────┬───────────────────────────────────┐
│                               │                                   │
│   ●  Remote Work Hub          │        欢迎回来                    │
│                               │   登录以继续你的远程工作台          │
│   跨时区协作，                  │                                   │
│   异步优先的远程团队工作台。     │   ┌─────────────────────────────┐  │
│                               │   │ 邮箱                        │  │
│   ── 今日团队概览 ──            │   │ [you@example.com        ]   │  │
│   ● 3 人在线                    │   └─────────────────────────────┘  │
│   ▦ 12 个任务进行中             │   ┌─────────────────────────────┐  │
│   ✎ 5 人已提交日报              │   │ 密码                        │  │
│                               │   │ [••••••••••          ] 👁   │  │
│   （左侧品牌区 40% 宽，          │   └─────────────────────────────┘  │
│    深蓝底 #0C66E4 或浅灰底）     │   ☐ 记住我      忘记密码？          │
│                               │   [        登 录              ]    │
│                               │   ─────── 或 ───────               │
│                               │   还没有账号？ 立即注册             │
└───────────────────────────────┴───────────────────────────────────┘
```

**登录页**
- 左侧品牌区（桌面 ≥1024px 显示）：品牌名 + 一句话价值主张 + 三行「今日团队概览」要点（用圆形图标 + 数字，非图表）。
- 右侧表单卡片：宽 400px，标题区 + 2 个字段 + 辅助行 + 主按钮（全宽 40px 高）。
- 字段：邮箱（`type=email`，前置 `Mail` 图标）、密码（后置眼睛图标切换明文）。
- 主按钮在提交中变为 loading（转圈 + 文案「登录中…」+ 禁用）；回车可提交。
- 底部一行：`还没有账号？立即注册`（链接跳 `/register`）。

**注册页**
- 与登录页同布局，字段：姓名、邮箱、密码、确认密码；主按钮「创建账号」。
- 密码规则以辅助文案常驻显示：「至少 8 位，含字母与数字」，输入时实时逐条变绿（不使用强度色条）。
- 底部：`已有账号？去登录`。

**状态稿要求**

| 状态       | 表现                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 默认       | 如上图                                                               |
| 提交中     | 按钮 loading，字段禁用，整卡轻微降低不透明度                          |
| 字段校验错误 | 输入框红边 + 下方 12px 红字（「请输入有效的邮箱地址」），聚焦首个错误字段 |
| 凭证错误   | 表单顶部信息条（红底浅色）：`邮箱或密码错误`，不指出具体哪个字段        |
| 邮箱已存在 | 邮箱字段下方红字：`该邮箱已被注册` + 行内文字链接「去登录」            |
| 登录过期   | 顶部蓝底信息条：`登录已过期，请重新登录`（跳转自受保护页面时出现）      |
| 服务不可用 | 表单顶部红条：`服务器内部错误，请稍后重试` + 「重试」按钮             |

## 7. 状态设计规范（**本文档重点，所有页面必须遵守**）

> 每个异步交互都必须能回答三个问题：**正在发生什么？为什么失败？我怎么继续？**

### 7.1 页面级错误（整页无法渲染）

- 布局：内容区垂直居中，最大宽 420px，左对齐图标 + 文案堆叠。
- 结构：48px 圆形浅红底 + `AlertTriangle` 图标 → 标题 16px/600 → 说明 14px muted → 按钮组（主「重试」+ 次「返回首页」）→ 底部 `12px mono` 错误码（如 `COMMON_INTERNAL_ERROR`，灰色，便于排障）。
- 按错误码映射标题与说明：

| 错误码 / 场景        | 标题             | 说明                                     | 主操作       |
| -------------------- | ---------------- | ---------------------------------------- | ------------ |
| `CLIENT_NETWORK_ERROR` | 网络连接失败     | 请检查网络后重试                         | 重试         |
| `COMMON_INTERNAL_ERROR` | 服务器出错了     | 稍后再试，或联系团队管理员               | 重试         |
| `AUTH_UNAUTHORIZED`  | 登录已过期       | 请重新登录以继续                         | 前往登录     |
| 无权限（403）        | 没有访问权限     | 当前账号无法查看此内容                   | 返回工作台   |
| 页面不存在（404）    | 页面不存在       | 链接可能已失效，或内容已被删除           | 返回工作台   |

### 7.2 区块级错误（页面局部失败）

- 卡片内联：左侧 24px 图标（`AlertCircle`，危险色）+ 中间标题 14px/500 + 说明 12px muted + 右侧「重试」文字按钮（蓝色，带 `RefreshCw` 图标）。
- 高 64px，浅红底（危险语义 5% 透明度），圆角 `md`。
- 未失败的区块必须保持正常可用（错误不扩散到整页）。

### 7.3 表单校验错误

- **时机**：失焦后校验 + 提交时全量校验；输入过程中不报错（降低噪音），但字数/格式类实时提示除外。
- **样式**：输入框 1px 红边 + focus 红色光晕；下方 12px 红字前带 `AlertCircle` 12px 图标；同时设置 `aria-invalid`。
- **服务端字段级错误**（`COMMON_VALIDATION_FAILED` + `details[].field`）：把错误信息挂到对应字段下方，并聚焦第一个出错字段；顶部不重复提示。
- **服务端结构级错误**（如 `AUTH_EMAIL_ALREADY_EXISTS`）：挂在相关字段下方（邮箱），可附带行内文字链接（「去登录」）。
- **凭证类错误**（`AUTH_INVALID_CREDENTIALS`）：出于安全考虑挂在表单顶部信息条，不指向具体字段。
- 表单有错误时主按钮**不置灰**（允许反复提交尝试），仅提交中禁用。

### 7.4 操作失败反馈（Toast / 回滚）

| 场景                     | 反馈                                                                     |
| ------------------------ | ------------------------------------------------------------------------ |
| 一般操作失败             | 顶部居中红色 Toast（sonner），文案取自 i18n 错误码，5 秒自动消失，带「重试」动作 |
| 乐观更新失败（拖拽、状态切换） | 先回滚到修改前状态，**再**弹 Toast + 目标元素抖动 1 次（300ms）           |
| 成功类操作               | 绿色 Toast，文案如「日报已提交」「设置已保存」，2 秒消失，不阻塞         |
| 网络断开（全局）         | 顶栏下方常驻琥珀色窄条：`网络连接已断开，正在重试…`，恢复后自动消失      |
| 登录过期（401）          | Toast `登录已过期，请重新登录` + 清除登录态 + 跳转 `/login?redirect=<当前路径>`，登录后回跳 |

### 7.5 加载态

- **禁止**使用整页转圈遮罩（除非阻塞式提交）。
- 列表 / 卡片 / 看板：使用骨架屏，形状与真实内容一致（头像圆、标题行、徽章位）。
- 看板拖拽落地后：保持卡片在目标位置（乐观更新），不做骨架闪烁。
- 表格 / 列表分页切换：保持表头，行区域覆盖 40% 白色遮罩（暗色为 40% 黑）。

### 7.6 空状态

- 结构：48px 线性图标（muted 色）→ 标题 16px/500（如「还没有任务」）→ 说明 14px muted（一句话讲清为什么空）→ 主操作按钮。
- **必须区分**「真的为空」与「筛选后为空」：后者文案为「没有符合当前筛选条件的任务」+ 次按钮「清除筛选」。
- 权限缺失 ≠ 空：无权限时用 §7.1 的 403 样式，不要显示空状态（避免误导）。

### 7.7 键盘与可达性

- 所有可交互元素有可见 focus 光晕（3px `--ring` 20%）。
- 看板卡片可 Tab 聚焦，聚焦时显示「移动到上一列 / 下一列」的操作提示（替代拖拽的键盘路径）。
- 状态色不可为唯一信息载体：状态点必须搭配文字，优先级徽章必须带文字。
- 弹窗：打开时焦点入内、`Esc` 关闭、关闭后焦点返回触发元素。

### 7.8 响应式降级

| 断点        | 行为                                                                 |
| ----------- | -------------------------------------------------------------------- |
| ≥1280px     | 完整布局，看板 4 列并排                                             |
| 1024–1279px | 侧边栏可折叠为图标条，看板 4 列仍并排但列宽压缩至 260px              |
| 768–1023px  | 侧边栏收进抽屉；看板横向滚动 + 顶部状态 Tab                          |
| <768px      | 底部 Tab 导航；团队页改单列卡片；看板改按状态分组的纵向列表；表单全宽 |
